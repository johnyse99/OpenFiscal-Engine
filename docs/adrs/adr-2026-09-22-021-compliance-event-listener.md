# Implement Event Listener Adapter for Compliance Audit

**Date:** 2026-09-22
**Status:** Accepted
**Commit:** feat(compliance): implement InvoiceIssuedEventListener adapter to trigger audit rules on document issuance
**ADR Number:** adr-2026-09-22-021
**Deciders:** Lead Architect, Juan S.

## Context

The `ComplianceAuditService` has been established to detect simulated operations and fiscal discrepancies. However, it requires a reactive entry point to execute automatically whenever a new fiscal document is legally generated by the Core Billing Context. We must bridge the event-driven foundation without tightly coupling the contexts.

## Decision

Created the `InvoiceIssuedEventListener` in the `com.openfiscal.compliance.infrastructure.adapter.in` package. This infrastructure adapter acts as the Inbound Port implementation for the Compliance Bounded Context. It listens for the `InvoiceIssuedDomainEvent`, maps the payload to an `AuditTransactionCommand`, and invokes the `ComplianceAuditService`.

## Consequences

- **Positive:** Successfully decouples the Core Billing Context from the Compliance Context. The billing core does not know the audit rules exist; it merely broadcasts the event.
- **Positive:** Enforces real-time auditing. Every issued invoice is immediately scanned against government blacklists.
- **Negative:** Because the invoice is evaluated immediately upon issuance, it is inherently flagged as `isFinanciallyReconciled = false` initially. A separate reconciliation event listener will be needed to update or clear discrepancy alerts once the bank payment arrives.
